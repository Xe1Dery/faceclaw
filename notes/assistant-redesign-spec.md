# Редизайн ассистента и уведомлений — ТЗ

Дата: 2026-11-09, утверждено. Макеты: `preview/assistant-ui/preview.html`
(генератор `tools/assistant-ui-preview.cjs`, позиция интерфейса —
`--vpos top|middle|bottom`, набор «сверху» — в `preview/assistant-ui-top/`).
Первая сборка с изменениями: APK 822.

## 1. Три примитива вместо четырёх слоёв

Сейчас: VoiceInputLayer (голосовой ввод), AssistantLayer (ответ ассистента),
ReminderLayer (напоминание), ProactiveDialogLayer (вопрос dialog_open) —
четыре полноэкранных оверлея с разными жестами.

Становится:

1. **Полоса** — единый примитив голосового ввода. Три входа: вызов
   ассистента, ответ на напоминание, ответ на вопрос.
2. **Окно диалога** — чат с агентом, полноценная сессия (не ваншот).
3. **Рамка уведомления** — напоминание/вопрос/alert без микрофона.

## 2. Полоса записи (макеты 01–04, 11–13)

Геометрия:

- Прижимается к **низу интерфейса**, а не экрана: нижний край полосы
  стоит ровно на нижней кромке интерфейса (под окном, поверх ряда
  переключателя — пока полоса открыта, ряд под ней). При Display →
  Vertical position = top всплывает под верхней полосой окон (макет 13).
- Ширина сразу полная (576 px, как окно приложения). Низ закреплён,
  полоса — самый нижний элемент интерфейса, поэтому при переносе фразы
  **растёт вверх**; максимум 4 строки, дальше хвост фразы скроллится
  внутри.
- Высота одной строки 44 px: иконка микрофона + текст (terminus16).
- Появление: на разблокированных очках — выезд снизу вверх поверх
  интерфейса (интерфейс остаётся видимым); на заблокированных — переходом
  яркости, интерфейс не поднимается, только полоса (макет 11).

Поведение:

- Иконка микрофона яркая во время записи; тускнеет, когда фраза
  зафиксирована молчанием.
- Во время набора подсказок нет, место под ними внизу полосы
  зарезервировано.
- После фиксации фразы внизу полосы — подсказки символами из
  принятого в приложении набора (`app/ui/gestures.ts`):
  `● отправить   ▲▼ заново   ●● закрыть`.
- Жесты (ровно как описаны):
  - **одиночный тап** — мгновенная отправка;
  - **скролл** — стереть и начать диктовку заново;
  - **двойной тап** — закрыть полосу.
- **Автоотправка** (существующая настройка skip-confirmation): после
  фиксации фразы — отсчёт 1,5 с, по нижнему краю полосы тает линия
  (макет 04). Тап отправляет сразу, скролл — переговорить. Без
  автоотправки отсчёта нет, полоса ждёт тапа.
- На заблокированных очках полоса закрывается вместе с экраном по его
  таймауту, сама раньше не гаснет.
- **Нет связи — ввод не начинается**: вместо полосы короткая рамка
  «Нет связи с OpenClaw» на том же месте (макет 12), гаснет сама через
  3 секунды. Связность = мост ассистента в состоянии connected
  (connecting тоже блокирует).

## 3. Окно диалога (макеты 05, 05b, 06, 07)

- Открывается вместо интерфейса: остаётся только окно. Входы: после
  отправки из полосы, тап по вопросу/напоминанию с ответом, вызов
  ассистента.
- Шапка: слева «OpenClaw», справа квадратик состояния связи (тот же
  рисунок, что на системной карточке; на главной квадратик остаётся).
- Лента чата: реплика пользователя с `> ` тусклее (170), ответ агента
  ярким (235) сразу под ней.
- **След действий** (`Thinking...`, `Exec: ...`) — тёмным (130) на месте
  будущего ответа, пока текст не пошёл; с первым символом ответа след
  уходит, ответ печатается в этом же месте (05 → 05b). Источник —
  существующий tool-activity поток моста.
- Ответ длиннее окна — стрелка-«ниже» в углу; скролл работает и во время
  генерации.
- После ответа — подсказка `● продолжить   ●● выйти`:
  - **одиночный тап** — снова поднимает полосу поверх окна (окно не
    исчезает); после отправки новый обмен добавляется в ту же ленту —
    это чат, а не одиночный обмен;
  - **двойной тап** — закрыть окно.
- **Выключение очков не закрывает окно**: оно сворачивается и
  возвращается тем же состоянием. Закрытым считается только после
  двойного тапа; при следующем открытии история начинается пусто.
- Пришедшее напоминание не трогает открытое окно диалога: рамка ложится
  поверх, разобрались с рамкой — окно там, где было.
- Без связи окно не открывается (та же рамка-причина).

## 4. Уведомления отделены от интерфейса (макеты 08–10)

- **Заблокированные очки**: уведомление приходит переходом яркости; за
  рамкой — ничего, интерфейс не поднимается. Только рамка по центру и
  её жесты.
- **Разблокированные очки**: интерфейс виден, рамка выезжает снизу вверх
  и лежит поверх (позиция как у ReminderLayer сегодня).
- Рамка — текущий рецепт ReminderLayer (фон 1, рамка 90, заголовок 200,
  текст 235, подсказка 150), подсказки символами:
  `● ответить   ●● пропустить`.
- Напоминание с ответом: тап поднимает **полосу** для голосового ответа;
  ответ уходит агенту, и если агент продолжает — открывается окно
  диалога. Двойной тап — пропустить (как сейчас).
- Вопрос агента (dialog_open) на заблокированных: рамка с вопросом и
  `● ответить голосом   ●● пропустить` (макет 10). Тап открывает полосу;
  после ответа дальше — **полноценное окно диалога**, а не одна реплика.
  Главный пункт: диалог становится сессией.

## 5. Инструменты агента

- `glasses.dialog_open` остаётся, результат меняется: вместо `{action,
  text}` одного обмена — `{action: answered | dismissed | no-answer,
  session: true}`; продолжение живёт в окне диалога, агент получает
  ответ как обычную реплику следующей итерацией.
- `glasses.reminder_show`: без ответа — рамка п.4; с интерактивным
  ответом — рамка + полоса по тапу.
- `glasses.show_alert` — рамка без кнопок, самозакрывающаяся.

## 6. Настройки

- Существующая автоотправка получает отсчёт; новых настроек нет.
- Подсказки жестов везде символами.

## 7. Чего не делаем

- Не трогаем: WSS-мост, потоковое распознавание, память OpenClaw,
  Glanceboard и системную карточку, часы, будильники.
- Изменений прошивки нет.
- Жестов вне списка (свайпы) не вводим.
